# Сквозной процесс: от источника до публикации

Для повторяемого или ответственного материала начинай с пакета:

```bash
python3 scripts/init_material.py "название материала"
```

Появляется папка `materials/<slug>/` с местом под источник, транскрипт, карту фактов, бриф, батарею хуков, оба варианта поста, медиа и отчёт приёмки.

## 1. Бриф

Зафиксируй известное: источник и права на него; канал, аудитория, желаемое действие; что просят — черновик, тест или публикацию; глубина и допустимость сжатия; обязательные ссылки, цитаты, кредиты; профиль голоса. Просьба «сделай черновик» — это черновик: разрешение на публикацию из неё не следует.

## 2. Вопросы — только существенные

Спрашивай, когда ответ меняет факты, адресата, позицию от первого лица, CTA, юридический риск или место публикации. Форматные мелочи решай разумным допущением и правь после первого черновика.

## 3. Карта фактов

До прозы — таблица: утверждение → источник → уверенность. Отдельно: точные цитаты с позициями, спорные места, таймкоды, права на медиа. Для чужого материала — трансформативный пост с явным разделением «автор источника считает» / «мой комментарий».

## 4. Тип поста и хуки

Выбери тип по [format-router.md](format-router.md), собери батарею по [hooks.md](hooks.md), выбери сильнейший хук, остальные — в `hooks.md` материала.

## 5. Черновик и редактура

Пиши черновик в голосе автора ([voice-memory.md](voice-memory.md)), потом три прохода редактуры и стилевой гейт ([redaktura.md](redaktura.md)):

```bash
python3 scripts/check_style.py materials/<slug>/post-plain.md --profile style-check.json
```

## 6. Формат доставки

| Формат | Лучше всего | Ограничение |
|---|---|---|
| Обычный пост | короткий текст, максимум совместимости | без сложной структуры |
| Альбом | 2–10 медиа | подпись до 1024 символов |
| Rich Message | лонгриды: таблицы, details, сноски, слайдшоу | старые клиенты покажут заглушку |

Plain-вариант готовится всегда; rich — когда структура улучшает понимание.

## 7. Валидация и превью

```bash
python3 scripts/validate_rich.py materials/<slug>/post-rich.html --media cover=cover.jpg
python3 scripts/preview_rich.py materials/<slug>/post-rich.html --out preview.html
python3 scripts/emoji_send.py materials/<slug>/post-plain.md   # превью с premium-эмодзи
```

Все ошибки валидатора чинятся до любого сетевого действия. Браузерное превью — черновая проверка композиции; рендер-эталон — Telegram Desktop и mobile.

## 8. Тест в изоляции

После явного одобрения теста:

```bash
python3 scripts/publish_rich.py materials/<slug>/post-rich.html \
  --photo cover=cover.jpg --send --confirm-target=-1001234567890
```

Проверь: desktop и mobile, превью в нотификации, пересылку, порядок медиа, узкие таблицы, раскрытые details, выбранный fallback.

## 9. Прод-гейт

Непосредственно перед продом покажи автору: финальный текст (или тест-сообщение), точные медиа, имя бота, точного адресата, известные ограничения совместимости. Затем — и только затем:

```bash
python3 scripts/publish_rich.py ... --environment production --send --confirm-target=<prod_id>
```

Успешный тест — отдельное событие; прод требует своего одобрения.

## 10. Замыкание петли

После одобрения материала предложи автору (выполняй после согласия):

- добавить пост в одобренные примеры голоса;
- записать в `MEMORY.md` новые правила из правок этого материала;
- повысить устойчивые правила в voice-profile;
- сохранить сработавшую структуру для этого канала.
